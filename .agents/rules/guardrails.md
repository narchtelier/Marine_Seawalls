# Repository Guardrails (Marine_Seawalls)

1. **Git Push Rules**: Don't push to GitHub unless explicitly instructed by the user.
2. **Git Pull Rules**: Don't pull from GitHub unless explicitly instructed by the user.
3. **Git Identity**: Always push and pull with Git from account `narchtelier` with email `narchtelier@gmail.com`.
4. **Response Style**: Be brief, concise and avoid long summaries/filler words to save token usage.
5. **Document Title**: Make sure the document title (e.g. `<title>` in HTML or app title) matches the repository name (`Marine_Seawalls`) so the browser always shows the repo name.
6. **Default Branch**: On the first git push, ensure the default main branch is named `main`. Do not change name to anything else.
7. **Git Commit Messages**: Give each git committed file or folder a unique description based on what the commit is about.
8. **Initial README.md**: Create an initial `README.md` which gives a paragraph summary of the project as a whole as well as a feature list, getting started, and controls at the first push commit to GitHub.
9. **README Header**: The `README.md` header should always be the same as the repository name (`Marine_Seawalls`).
10. **README Updates**: Update `README.md` before each push commit to GitHub to include any major new features, getting started, or controls. Do not update `README.md` with minor changes.
11. **Git Commit Tracking**: Don't keep track of git commits after each instruction or git diff caching; only check changes when merging and pushing to git.
12. **Context Compaction**: Don't compact the context unless explicitly told to.
